# PCB Layout — Stackup, Floorplan, Routing Rules

**Board: 80 × 68 mm, 4 layers, 1.6 mm, 2 oz outer copper.**
Placement is generated by `scripts/gen_pcb.py` and is **DRC-clean at
0 violations** (382 unconnected items is expected — nothing is routed yet).

---

## The one number that matters

Everything else on this board is ordinary. The commutation loop is not:

```
bulk ceramic → high-side FET → phase node → low-side FET → shunt → PGND → ceramic
```

At 150 A with 50 ns edges, `di/dt` = **3 A/ns**. Every 1 nH of loop
inductance adds 3 V of overshoot to a 40 V FET already sitting on a
12.6 V rail.

Loop inductance is set by the distance to the **return plane**, not by
how cleverly the FETs are arranged (`L = μ₀·d·l/w`):

| Return path | `d` | `L_loop` | Overshoot | V_DS peak |
|---|---:|---:|---:|---:|
| High side top / low side bottom | 1.60 mm | 4.36 nH | 13.1 V | 25.7 V |
| All FETs top, return on B.Cu | 1.60 mm | 4.36 nH | 13.1 V | 25.7 V |
| All FETs top, In1 at 0.5 mm (stock 4-layer) | 0.50 mm | 1.36 nH | 4.1 V | 16.7 V |
| **All FETs top, In1 at 0.20 mm (this board)** | **0.20 mm** | **0.54 nH** | **1.6 V** | **14.2 V** |

Splitting high-side and low-side across the board is intuitively
appealing and about **8× worse**, because it forces the return current
through the full board thickness. So: all twelve FETs on F.Cu, with an
unbroken ground plane 0.2 mm beneath them.

## Stackup — tell the fab the 0.2 mm is not negotiable

```
F.Cu     2 oz (70 µm)   DC+ pour, 12 FETs, phase pours, ceramics, shunt, driver
   ──── 0.20 mm prepreg ────   ← the whole trick is this number
In1.Cu   1 oz           SOLID PGND. No splits under the bridge, ever.
   ──── 0.97 mm core ────
In2.Cu   1 oz           gate + sense routing, AGND island under the driver
   ──── 0.20 mm prepreg ────
B.Cu     2 oz (70 µm)   phase lanes to the motor pads, logic, thermal copper
```

A house-standard symmetric 4-layer stack (0.5/0.5/0.5) triples the loop
inductance. If the fab substitutes it, the design has lost most of its
margin.

## Floorplan

```
   0                                                              80 mm
 0 ┌──────────────────────────────────────────────────────────────┐
   │ (o)          ╔══════ DC+ pour ══════════════════════════╗    │
   │  J101 ⊙      ║  24 × 10 µF ceramic, 3 rows              ║    │
   │  VBAT+   C101║  ── directly above the high-side drains ─║    │
15 │  J102 ⊙  C102║  Q301 Q302 │ Q305 Q306 │ Q309 Q310  ← HS ║    │
   │  VBAT-   C103║  ═══ PHASE_A ═══ PHASE_B ═══ PHASE_C ════║    │
30 │  D101 TVS    ║  Q303 Q304 │ Q307 Q308 │ Q311 Q312  ← LS ║    │
   │              ║  RS301..RS304  0.25 mΩ shunt             ║    │
40 │              ╚══════════════════════════════════════════╝    │
   │   gate nets  C201..C208      U201 DRV8323R     L201  R201-211│
55 │              ┌──────────┬──────────┬──────────┐              │
   │              │ PHASE_A  │ PHASE_B  │ PHASE_C  │  lanes on    │
   │ (o)          ⊙ J301     ⊙ J302     ⊙ J303     │  B.Cu        │
68 └──────────────────────────────────────────────────────────────┘
        B.Cu x < 29: MCU, 6 × interlock, headers, decoupling
```

Current flows **down each column**: DC+ → HS drain → HS source → phase →
LS drain → LS source → shunt → PGND. All three columns are identical, so
the three phases commutate the same way. FETs are rotated 90° so the
source/gate edge faces down and the big centre drain pad faces the pour
above it — rotating them the other way makes every phase current double
back on itself and doubles the loop area.

### Layer duties

| Layer | Carries |
|---|---|
| **F.Cu** | DC+ pour, all 12 FETs, phase pours, ceramics, shunt, gate driver, gate networks |
| **In1.Cu** | **Solid PGND.** The return for every commutation loop |
| **In2.Cu** | Gate and sense routing, AGND island under the driver |
| **B.Cu** | Three phase lanes down to the motor terminals, all logic at x < 29, thermal copper |

The three B.Cu phase lanes (x 29.5–38.5, 45.5–54.5, 61.5–70.5, y 22–63)
are kept clear of every part. That is a *routing convenience*, not an
inductance requirement — the motor lead is in series with a 10–100 µH
winding, so its own inductance is irrelevant.

## Routing rules, in priority order

1. **Never split In1.Cu under the bridge.** A slot in the return plane
   forces the return current around it and undoes the entire stackup
   argument. No signals on In1 in the bridge area, at all.
2. **Ceramics first, then everything else.** Each 10 µF must reach the
   DC+ pour and drop to In1 through its own via pair, as short as
   possible. These are the loop's high-frequency source; the
   electrolytics are far too slow to participate.
3. **Phase pours: wide enough for 100 A, and no wider.** The phase node
   is the board's dv/dt aggressor. 2 oz copper at 100 A with a 20 °C rise
   needs roughly 20 mm width, or fewer mm plus via stitching to B.Cu.
4. **Shunt sense must be Kelvin (ESC-005).** `SPA`/`SNA` tap the shunt
   pads directly, never the power pour. At 0.25 mΩ, a few mΩ of shared
   trace is a large fractional error.
5. **Gate loops tight and equal.** Route each `GHx`/`GLx` with its return
   (`SHx` for high side, `SHUNT_P` for low side) as a pair. Length
   *mismatch* between phases is not critical — 14 mm of trace is ~84 ps,
   against 625 ns of dead time — but loop *area* is.
6. **Thermal vias under U201.** The stock `_ThermalVias` footprint was
   deliberately **not** used: it embeds 0.2 mm vias and this board is
   2 oz, where 0.3 mm is the realistic fab minimum. Place a 0.3 mm via
   array by hand on the exposed pad.
7. **Keep the phase lanes off the logic.** Already true by placement;
   preserve it when routing.

## Thermals

~19 W at 100 A continuous into 80 × 68 mm is about **0.35 W/cm²** —
better than the 1.1 W/cm² the earlier 50 × 35 mm estimate in
`power-budget.md` assumed, but still **not passively coolable**. The
design assumes propwash or forced air (ESC-012). Bench testing at 100 A
needs a fan.

The shunt is the hottest discrete at 2.5 W; give it copper on both outer
layers and stitch generously.

## Reproducing

```bash
pgrep -fil kicad        # must be empty — the script edits the .kicad_pcb

/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/\
Versions/Current/bin/python3 scripts/gen_pcb.py

kicad-cli pcb drc --output /tmp/drc.rpt --severity-error \
    design/dshot-esc-100a.kicad_pcb        # currently 0 violations
```

`gen_pcb.py` **edits the board in place** so the `(path ...)` linkage from
"Update PCB from Schematic" survives. It also clears and re-adds its own
zones each run — `pcbnew.SaveBoard()` rewrites every UUID, so deduping by
UUID silently accumulated 14 stacked pours before this was caught.

> Once hand-routing starts, stop running `gen_pcb.py`: it re-places every
> footprint. Tracks and hand-drawn zones would survive, but the placement
> they were routed to would not.
